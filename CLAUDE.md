# nullion

A daily computing trivia game in the style of krillion.io. There are 7 prompts a day ("Name a type of lock"). Each accepted answer pushes stack frames, and the player's cursor descends the software stack, from Application down to Ring −3. Pixel art. The site is static, with GitHub Pages as the target.

Current stage: **offline playtest prototype.** The open question is which answer dataset and rarity strategy to use, and playtesting decides it. Don't build backend infrastructure before playtests justify it.

What's next lives in `ROADMAP.md`; the next milestone is question and answer generation. The Endless stack's design lives in `ENDLESS-PLAN.md`, and the 29-layer setpiece/readability pass lives in `LAYER-PLAN.md`.

## Version

`package.json`'s `version` is the one source (semver; the pre-release tag is the stage: `0.1.0-alpha`). Code reads it from `src/version.ts` (`VERSION`, `STAGE`, `VERSION_LABEL`); it shows on the title screen, in Settings, at the foot of the end card, and as `nullion.version` in the browser console. Bump the minor version for a release-worthy batch and the patch for fixes, add a `CHANGELOG.md` entry, and tag the commit `v<version>`. There is no "launch": the goal is a stable 1.0 (stage bars in `CHANGELOG.md` and `ROADMAP.md`).

- `npm test`: vitest. Covers core rules, matching, data integrity, obvious-answer checks, the game loop, Field Manual registry/store (`src/game/manual.test.ts`), v4 placement (`V4_SWEEP=1` for a 200-seed sweep), reaction timelines (`src/render/reaction-fx.test.ts`), reveal layout overlaps (`src/ui/reveal-layout.test.ts`), RHS layer stack (`src/ui/layer-stack.test.ts`), and the HUD flow in happy-dom (`src/ui/hud.test.ts`).
- `npm run typecheck`
- `npm run build`: production build into `dist/`. The debug menu is stripped out.
- `npm run build:debug`: same, with the debug menu, into `dist-debug/`.
- Debug deep links: `?depth=N` opens scroll-only mode parked at depth N. `?look.<slot>=<value>` sets a look (saved like the menu does), e.g. `?look.rain=hex`. The world art is v4 only: a seeded world of hand-drawn entities (`src/render/art-v4.ts` + `src/render/v4/`); shared canvas helpers (`hash`, `Band`, `FONT`, the `Seam` type) live in `src/render/art-common.ts`; what each layer looks like is in `src/layers/` (see Layers above).
- More debug links: `?seed=N` pins v4's world seed; `?perf=1` times 120 scene frames and writes `PERF avg/p95/max` into the title and a box on the page (headless only schedules frames for screenshots, and virtual time freezes `performance.now()`, so measure over the DevTools protocol in real time).

## Layers: one module each (`src/layers/`)

- **A layer's presentation lives in one object, `LayerArt` (`src/layers/types.ts`), in one module, `src/layers/<layer-id>.ts`** (31 files: Daily, Endless and True Endless share ids; `kernel` is one layer). `src/layers/index.ts` is the registry, `LAYER_ART: Record<LayerId, LayerArt>`, so a layer without a module is a compile error. Callers read `LAYER_ART[id].<field>` and never switch on a layer id or keep a per-layer table. `src/core/layers.ts` stays pure and DOM-free: ids, order, names, thresholds, modes (tests pin the thresholds).
- **What a `LayerArt` holds:** `family` (its Daily layer: the Field Manual files critters and unlock state under it), `blurb`, `palette`, `form` (console idiom), `cursor`, `stackTheme` (RHS stack colours and 9×9 icon), `topicTags`, `library` (a `LayerSpec`: own props, anchors, borrow, density, floor), `open` (first layer open upward, last downward), `frozenTime` (Ring −2), `keepOut` / `floors` (world), `fog`, `nameTopOffset`, `background`, `setpiece.base/detail`, `seam`, `ambient`, `critters` (motions, count, exit labels, `draw`, `alt`, `hop`) and `sound` (timbre, ambience level and drones, critter exit blip, `critterCall`, `artifact`, `cross`; recipes play through a `SoundKit`).
- **Adding a layer:** add its id to `src/core/layers.ts` (the layer lists and the id type), write `src/layers/<id>.ts` exporting one `LayerArt` (copy the closest layer; the compiler lists every missing field), and add one import plus one entry to `src/layers/index.ts`. Nothing else switches on layers. A layer that reuses a sibling's piece imports it from that module (`critterCall: application.sound.critterCall`, `icon: drivers.stackTheme.icon`); pieces shared by several layers live in `src/layers/shared/` (`draw-kit.ts` pixel helpers, `ambient-kit.ts`, and the `*-props.ts` helpers several layers' entities draw with). Not per-layer data, so still in code: boundary crossing effects (tear at the syscall, mirror at VM exit, SMI freeze, ME 1-bit) in `scene.ts`, and the Endless/True Endless stack geometry in `core/layers.ts`.

## v4 world (entities and placement)

- Each layer has a library of 20+ entity types plus 1–2 anchor structures (in each layer's module, `src/layers/<layer-id>.ts`; `v4/libraries.ts` builds `V4_LIBRARIES` from every layer's `library` spec). An entity is `ent(id, sizes, draw, { anim, text, noFlip, cap, weight, floor, tags })`: `draw` is the static body, baked once per palette into a cached sprite; `anim` is a small live overlay on art time. Draw only through the `Pen` (`v4/kit.ts`), which snaps every solid colour to the band's palette; only `p.glow` (light) dithers.
- **One library builder (`v4/library.ts`, `buildLibraries`).** Every layer's `Library` is built from a `LayerSpec`: its own entities, its anchors, density, and an optional borrow `{ from, prefix, upTo }` that fills up to `upTo` types with renamed copies of the donor layer's own props (`${prefix}-${donor.id}`; the naming desk keys its records by these ids, so don't change the scheme). It `enforce()`s the 20-type minimum, unique ids, a donor big enough to fill, and that floor props and `floorOffset` go together. There is no other way to compose a library: Endless layers' extra props live in their own modules, and the Endless donor `mix()` is gone.
- **Entity metadata lives on the entity.** `floor: true` puts an entity on the layer's floor line (`floorOffset` in the spec; Libraries 4, Userspace 6); borrowed copies never keep it. `tags` overrides the entity's topic tags; unset, it gets its layer's defaults from its `topicTags` (`LAYER_TOPIC_TAGS` in `v4/libraries.ts` is read off the registry, so a new layer without tags is a compile error). Topic tags are never derived from id patterns (the old prefix regexes went stale), and `tagsForEntity(def)` throws on an entity that never went through the builder.
- Placement (`v4/place.ts`, pure and unit-tested in `place.test.ts`) runs once per (seed, viewport width), never per frame: anchors first, beside the centre; then a rejection-sampled scatter with bounded attempts that never overlaps, stays out of the cursor lane and keep-outs (arrival-title band, Ring −3 core and rails, floors), allows only small text-free props in the lanes under the console card and header chips, caps each type per screen height, picks least-used types first, and borrows neighbour types near band edges (bleed). A sparse fogged far plane sits behind. It `enforce()`s that libraries are complete, anchors fit and enough of the scatter lands.
- Seeding: two streams. Anchors (setpieces and landmarks) are seeded by the puzzle number, so everyone recognises the same world on a given day and it changes at rollover. Minor scatter and critters use a second stream derived from the same puzzle number, so the whole world is the same for everyone on a given day (decided 2026-11-26; per-visit scatter was tried and reverted). `?seed=N` pins both. The debug rail's dice button rerolls it (its tooltip shows the seed for `?seed=N`). The rail's lane is kept clear in debug builds by dropping entities under it after placement, so the rest of the layout is identical to production.
- Known limit: panels are fixed to the screen and the world scrolls under them, so "keep-out under panels" is per x-lane, not absolute; the arrival title is kept clear for landings in a layer's first frame.
- System Biosphere (`src/render/critters.ts`): every layer has its own living critters animated on `artTime` (songbirds in Application, bouncy helper blobs in Runtime, bookworm blobs in Libraries, horned daemons in Userspace, brisk thread-bots in Kernel, fast bus-beetles in Drivers, sentinel drones in Firmware, twin mirror-wisps in Ring −1, frozen mid-leap silhouettes in Ring −2, 1-bit bit-motes in Ring −3). Each layer's `critters` spec has a set of `MotionType`s (`src/render/motion.ts`) and a `draw`; some layers add an alternate species on odd variants (`critters.alt`: its own motions and sprite, so a layer cannot have one without the other). Critters come with stereo-panned critter SFX (`sound.playCritter`) and visual chirp pips. Static scatter density (`library.density`) is tuned for breathing room, and literal static puns (`kr-watchdog` dog, `kr-oom` skull, static `us-daemon` / `kr-kthread`) were replaced with clean hardware props.

## Locked design decisions

- **Tiers.** Rarer means harder to reproduce. Frames per answer:

  | Tier | Frames |
  |---|---|
  | Off-by-one | 1 |
  | Works on my machine | 1 |
  | Null pointer exception | 2 |
  | Memory leak | 3 |
  | Race condition | 5 |
  | Heisenbug | 8 |
  | Bit Flip | 13 |

  - Works on my machine mirrors krillion's "Too Clever": the "obscure" pick everyone reaches for.
  - Bit Flip is exactly one hand-picked answer per question. Data loading enforces this.
- **Layers** (in `src/core/layers.ts`):
  - Thresholds: Application 0, Runtime 3, Libraries 6, OS userspace 10, Kernel 15 (syscall boundary), Drivers 22, Firmware 31, Ring −1 42, Ring −2 58, Ring −3 91. Rebalanced 2026-11-26 after a player-profile simulation showed the old ones kept typical players above the syscall and made the rings near-unreachable.
  - Intended feel: a typical day crosses into the kernel; a day of mostly deep cuts reaches Ring −1; Ring −2 needs at least one Bit Flip; Ring −3 needs a perfect day.
  - Only a perfect day (7 × 13 frames) reaches Ring −3. Tests pin these properties; change a test only on purpose.
- **Data model.** A term is stored once, with tags. Each tag carries that term's tier for that category, so "heisenbug" is Works-on-my-machine for "Name a type of bug". Each question queries one tag.
  - Duplicate keys within a category are a data bug and throw at load time.
- **Answer sets are swappable** (`AnswerSet` in `src/core/answers.ts`). Register new ones in `SETS` in `src/main.ts` to compare them in the debug menu.
- **Missed-answer reports and question submissions** go through prefilled GitHub Issue links. A GitHub account is required, and that's acceptable. Reports are never auto-accepted.
- **Day rollover:** local midnight, Wordle-style. `src/core/day.ts` has the epoch.

## Visual alternatives

Looks are drafted live:
1. Add an option to `LOOK_SLOTS` in `src/looks.ts`.
2. Branch on `look('slot')` where it's drawn, usually `src/render/scene.ts`.

The debug menu builds its controls from that table. Keep alternatives switchable rather than replacing the current look, so the user can compare them in the site.

Reduced motion must keep working: flashes, tearing, rain, flicker, cursor sway and bubbles all check `reducedMotion()`; the HUD adds `.still` so floating panels stop, and v4 art animates on a clock that is 0 under reduced motion.

Looks are saved under `nullion.looks.4`; bump the key when a default changes and old saved choices should not mask it.

The day's record of answers lives in the end-of-day card and the share text; there is no running panel. The card is a backtrace, most recent round first (#0 = the last answer): each row shows its frame numbers and the tier's cursor icon, and opens in place on hover, focus or tap to the tier and the answer. Each row keeps an empty last slot for a future dropdown of other players' answers. There is no replay.

Drafts are exempt only from the rules that need hand-written prose (rumour, name wording, blurb and note shape and length, detail note length).
  - **Generator (`python3 -I scripts/manual-from-desk.py [--dry-run]`):** drafts a `status: draft` file for every naming-desk record whose entity is in `design/naming/inventory.json`, is not deleted, not folded into another record, has a resolved name (write-in, or chosen proposal), and no existing manual file covers (by entity id, or critter layer). Verified merges and variants into a drafted record become extra sightings in their layers. Name from the desk, kind from the inventory, rarity common, tag `NAME(<home chapter>)`, blurb and note from the desk description and proposal `depicts` / `concept`, detail note from `depicts`. It never overwrites or edits an existing file ("your edits win"), so rerunning only drafts new records; prints counts.

- **Question-reactive background props (`src/render/v4/topics.ts`):** many-to-many `TopicTag` mapping: questions by id and keyword, entities by their own `tags` or their layer's `LAYER_TOPIC_TAGS`; a deterministic subset of eligible non-anchor near-plane props flip in place to palette-snapped animated topic displays clipped strictly to `(x, y, w, h)` with a flat top bezel for critters.

- **End-of-day backtrace & answer sheet (`src/ui/answer-sheet.ts`):** each row has a `▾` dropdown showing the prompt's answers grouped by tier (deterministic 8 per tier with `+N more`, own answer marked, and inline `note:` whispers on `Bit Flip` / `Works on my machine` picks).
- **Typo correction & settings:** player settings live behind the gear chip (beside the quick mute chip) in the header (`src/ui/prefs-menu.ts`).
- **Tier icons (`src/ui/tier-icons.ts`):** the cursor in each tier's reaction pose, used in the title tier guide, the result backtrace card, and the debug rail. Share text keeps emoji.
- **Console forms (`src/ui/forms.ts`; a layer's `form` picks one):** the card takes the layer's idiom (GUI dialog, REPL, shell, serial console, BIOS setup, hypervisor log, SMM dump, raw entry).

## Conventions

- Invariants use `enforce()` from `src/core/enforce.ts` and throw loudly. Expected conditions are handled explicitly, never with silent defaults. Missing localStorage is an expected condition.
- Keep game rules in `src/core` and `src/game`, free of DOM code, and test them.
- `src/data/sample.ts` holds hand-written placeholder tiers, not the output of a rarity signal.

## Stack modes (`src/core/modes.ts`)

`MODE_RULES: Record<StackMode, ModeRules>` (`rulesFor(mode)`) holds everything a mode decides: layer stack and max depth, prompt source (the day's 7 vs an anti-repeat pool), strikes and watchdog, whether it persists the daily save / counts stats / shows the next-day countdown, round slots vs fuses, end-card headline and chip, share title and glyph cap, world geometry (per-frame height, last-layer px), kernel-rain layer, unlisted crossing effect, sound-bed layer, realm nav, forced scroll mode, and scroll steps. `layersFor`, `maxDepthFor`, `layerIndexAt`, `layerAt`, `layerById` and `ANSWER_MS` also live there (`layers.ts` is layer data only). Never compare mode strings in callers: add a rule. Strings are compared only where they are identity (the `?endless=` param and debug dropdown in `main.ts` / `Hud.setEndlessMode`).

## Endless mode

Debug-only for now (`?endless=1` or the header chip). A 29-layer stack to about 2,500 frames (`ENDLESS_LAYERS` in `src/core/layers.ts`), a per-prompt watchdog that tightens with depth (`endlessAnswerMs`, in `src/core/modes.ts`), 3 strikes and a `KERNEL PANIC` card, and an anti-repeat prompt bag. It draws from the same question bank as the daily game, so it only plays well once the bank is large.

## Answer bank

- **Source of truth: `bank/<domain>/<id>.md`**, one human-edited Markdown file per category. The strict grammar and its error messages live in `src/data/bank-format.ts`:
  - a `# prompt` line, then `id: · domain: · status:` (draft, approved or retired), then an optional `> Accepts:` line;
  - one `## <tier name>` section per tier, in tier order, holding `- answer | alias | alias` lines, each with an optional indented `note:`;
  - finally `## Inbox`, holding unreviewed candidates with `(suggested: tier)`. These are never accepted in play.
  - An approved category needs exactly one Bit Flip and at least one Works on my machine.
- **`bank/index.md`** is generated by `npm run bank:index` and is also the runtime manifest: `main.ts` picks the day's prompts from the approved rows, then lazily loads only those files (`src/data/bank.ts`, one chunk each; all approved files for Endless). `npm test` fails if the index is stale or any file is off-grammar.
- **Matching (`src/core/match.ts`, 2026-11-27):** a guess is checked in order: (1) exact name or alias, normalized; (2) other phrasings of the same answer, as exact: a leading a/an/the, a plural, then the prompt's own noun or a generic one on the end ("mutex locks", "ext4 filesystem"), smallest change first, and only when it names one entry; (3) four letters: an adjacent swap only, never a changed letter (ext3 ≠ ext4); (4) the typo budget (1 at 5+ letters, 2 at 9+). A one-typo correction on a 7+ letter name is `sure` and never asks, even with "ask first"; ambiguity is always rejected, never guessed. `bank.test.ts` checks across the approved bank that no phrasing lands on a different answer. `scripts/bank-dupes.py` lists entries that are one answer said two ways ("Sinusoidal" vs "Sinusoidal projection"), for merging.
- **What counts as an answer (decided 2026-11-26): named kinds.**
  - Anything experts name as a kind of the thing, in a real codebase, its docs or a paper, gets its own entry and its own tier. That covers designs (MCS lock) and named system primitives (Windows ERESOURCE, push lock and SRW lock; FreeBSD rmlock and sx lock; PostgreSQL LWLock and lock modes).
  - Plain bindings of a generic name are aliases of that name: `std::mutex` and `pthread_mutex` belong to mutex, `ReentrantLock` to recursive mutex.
  - API calls, specific instances (`mmap_lock`), config symbols and states never count.
  - A player gives one answer per prompt, so overlapping entries never double-score. The rule only decides what's accepted and whether a system's own name earns its own tier.
  - Category-specific limits go in the file's `> Accepts:` line.
- **Recall comes from real sources, not memory.** `scripts/mine-heads.py <bank file> <head,nouns> <dirs…>` mines phrases and identifiers ending in a head noun from source trees in `~/nullion-corpora/src`. Those are sparse clones: FreeBSD `share/man/man9`, MicrosoftDocs `windows-driver-docs` (kernel) and `win32` (Sync), and PostgreSQL docs plus `lmgr`. The output is noisy, so an agent applies the membership rule to it, and survivors go through the scorer into the Inbox. Add source trees per domain as categories need them.
- **Unconfirmed answers (decided 2026-11-26).**
  - A tiered line ending in `(auto)` was accepted by the pipeline and not yet confirmed by a person. It plays its **full tier**, and players are never shown that an answer is unconfirmed. An earlier Memory-leak cap made deep cuts pay 3 frames instead of 8 and was dropped.
  - `(auto)` is a review label only. Precision samples (95–100% on sourced answers) are the guard against wrong accepts.
  - Delete the marker to confirm an answer. Bit Flip and Works on my machine can never be `(auto)`.
  - The index counts unconfirmed answers per category.
- **Harvesting a category: one command** (error classes behind the steps: `research/inbox-review-2026-11-26.md`):
  `python3 -I scripts/bank/pipeline.py <id> [--from <stage>] [--dry-run]`, or `--batch N [--from-rank K] [--jobs J]` for the next N not-done categories in `design/triage/ranked.md` order (keep/fix only; `cut` is skipped, `merge` is noted). Stdlib only (`scripts/bank/llm.py` wraps the LLM calls).
  - Stages: plan (an LLM drafts `scripts/bank/plans/<id>.json` if missing; **flagged for the owner to veto**) → harvest → filter (two independent passes per batch with `prompts/filter.md`: A = Gemini via `agy`, B = Claude Haiku) → compare → escalate (Gemini; `"confidence": "low"` goes to the Inbox) → merge (merge-mined, score-candidates, `bank:index`; a fresh draft's Bit Flip and Works on my machine pins are chosen by Haiku and **flagged for the owner**) → obvious (Haiku drafts `scripts/bank/obvious-draft/<id>.json` if missing, then `apply-obvious.py`; **approval moves the list to `scripts/bank/obvious/`**, because `obvious.test.ts` rejects lists for non-approved categories) → dupes (report only) → links (`design/links/`) → precision (Haiku reviewer, **gate: 90%**) → report (`bank/reports/<id>.md` gets a pipeline section: gates, tier counts, pick shortlists, link coverage).
  - State: `scripts/bank/runs/<id>/state.json` plus `logs/<stage>.log`. Done stages are skipped on rerun; finished sub-steps (a valid filter pass) are reused; `--from <stage>` forgets that stage and later ones. The first failing stage or gate stops the run, non-zero, loudly. LLM output is schema-validated, retried once, then fails.
  - The category stays `status: draft`. Approval is a person's call: vet the flagged plan, pins and obvious list, fix what the precision sample found, then flip the status.
  - A plan may also use `extract` (regex over a registry file in a local tree, e.g. the Complexity Zoo's `classes.txt`) next to `heads` and `listings`.
- **Your edits win.** `scripts/score-candidates.py <candidates.json> ~/nullion-corpora` fills the tiers of a category that has none yet (a fresh draft). Once a file has tiered answers it never moves or deletes a line: it appends new candidates to the Inbox with a suggested tier, and `bank/reports/<id>.md` lists counts, scores and answers whose file tier differs from the scored tier by more than one.
- **Scoring:**
  - The corpora live in `~/nullion-corpora`, indexed by `scripts/index-corpora.py` with SQLite FTS5 and the porter tokenizer: dblp titles, arXiv cs title and abstract (`scripts/harvest-arxiv.py`) and kernel Documentation paragraphs.
  - Counts are normalised per category against the 3rd-largest count.
  - Absolute cut-offs (`CUTOFFS`, fitted to the pilot's judge calls) map score to tier, so adding obscure candidates never pushes common answers deeper.
  - Counts decide only with at least 10 hits in some corpus; below that the candidate's `judge` tier decides, and a weak candidate without one is an error. Bit Flip and Works on my machine are pinned.
- **The "Answer set" menu** switches between `bank` (the default) and `sample` (the hand-written `src/data/sample.ts`, kept for comparison).
- **Status, 2026-11-26:** 34 approved categories (precision 95–100% on 20-answer samples; `Bit Flip` and `Works on my machine` picks carry 1-sentence `note:` whispers) and 159 drafts.

## Persistence

- **Daily save (`src/game/daily-save.ts`, `Game.snapshot/restore`):** today's game lives in localStorage under `nullion.daily.<puzzle>`: every round's accepted answer, extras, rejected guesses, timeout/skip flags, the phase and its deadlines. Reopening the same local day restores it exactly; a finished day reopens on the end card; the next puzzle number starts fresh and old saves are pruned.
- **Anti-cheese:** deadlines are wall-clock (`Date.now`, injected into `Game` as `now`; `src/game` never reads a clock). The reading start and the answer deadline are stored, answer deadlines chain from the end of reading, and a tick after being away replays reading, answering and the timeout. Closing, reloading or hiding the page never pauses or resets the watchdog.
- **Not saved:** Endless and every debug mode (unlimited, chosen date, no timer, scroll-only, `?depth`) never read or write the save (`canPersistDaily`). No storage is an expected condition: the game just doesn't persist. A corrupt or mismatched save is never silently reset: it is removed, a visible notice says why, and the day starts fresh.
- **Field Manual save (`src/game/manual-save.ts`, `ManualStore` in `src/game/manual.ts`):** version 2 under `nullion.manual.v2` (debug: `nullion.debug.manual.v2`). For each `(entry, layer)` appearance it keeps the first-sighting stamp `{ at, puzzle, prompt? }`, plus the set of "wet" stamps not yet viewed (unread). `main.ts` supplies the sighting context (puzzle, current prompt). Production migrates the old shared `nullion.manual.v1` key once (undated stamps); debug builds never touch it. A corrupt save is removed with a visible notice. Sightings of entries or layers that no longer exist are dropped with a notice naming them, and the cleaned save is written back. The debug rail's `Unlock all` toggle is an in-memory overlay that never changes saved discoveries.
- **End card:** counts down to local midnight, links into the Field Manual with any unread count, and offers a reload once the next puzzle opens.
