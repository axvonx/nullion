# nullion

A daily computing trivia game in the style of krillion.io. There are 7 prompts a day ("Name a type of lock"). Each accepted answer pushes stack frames, and the player's cursor descends the software stack, from Application down to Ring −3. Pixel art. The site is static, with GitHub Pages as the target.

Current stage: **offline playtest prototype.** The open question is which answer dataset and rarity strategy to use, and playtesting decides it. Don't build backend infrastructure before playtests justify it.

The owner's open review queue (content approvals, naming, writing, feel checks) is `REVIEW.md`; check it first. What's next lives in `ROADMAP.md`; the next milestone is question and answer generation. The Endless stack's design lives in `ENDLESS-PLAN.md`, and the 29-layer setpiece/readability pass lives in `LAYER-PLAN.md`.

## Version

`package.json`'s `version` is the one source (semver; the pre-release tag is the stage: `0.1.0-alpha`). Code reads it from `src/version.ts` (`VERSION`, `STAGE`, `VERSION_LABEL`); it shows on the title screen, in Settings, at the foot of the end card, and as `nullion.version` in the browser console. Bump the minor version for a release-worthy batch and the patch for fixes, add a `CHANGELOG.md` entry, and tag the commit `v<version>`. There is no "launch": the goal is a stable 1.0 (stage bars in `CHANGELOG.md` and `ROADMAP.md`).

- `npm run build`: production build into `dist/`. The debug menu is stripped out.
- `npm run build:debug`: same, with the debug menu, into `dist-debug/`.
- `npm run review`: the owner's review desk (`scripts/review-desk.mjs` + `design/review/index.html`, on 127.0.0.1), which saves decisions to `design/review/decisions.json`. `npm run naming`: the naming desk (http://127.0.0.1:4870).

## Layers: one module each (`src/layers/`)

- **A layer's presentation lives in one object, `LayerArt` (`src/layers/types.ts`), in one module, `src/layers/<layer-id>.ts`** (31 files: Daily, Endless and True Endless share ids; `kernel` is one layer). `src/layers/index.ts` is the registry, `LAYER_ART: Record<LayerId, LayerArt>`, so a layer without a module is a compile error. Callers read `LAYER_ART[id].<field>` and never switch on a layer id or keep a per-layer table. `src/core/layers.ts` stays pure and DOM-free: ids, order, names, thresholds, modes (tests pin the thresholds).
- **What a `LayerArt` holds:** `family` (its Daily layer: the Field Manual files critters and unlock state under it), `blurb`, `palette`, `form` (console idiom), `cursor`, `stackTheme` (RHS stack colours and 9×9 icon), `topicTags`, `library` (a `LayerSpec`: own props, anchors, borrow, density, floor), `open` (first layer open upward, last downward), `frozenTime` (Ring −2), `keepOut` / `floors` (world), `fog`, `nameTopOffset`, `background`, `setpiece.base/detail`, `seam`, `ambient`, `critters` (motions, count, exit labels, `draw`, `alt`, `hop`) and `sound` (timbre, ambience level and drones, critter exit blip, `critterCall`, `artifact`, `cross`; recipes play through a `SoundKit`).
- **Adding a layer:** add its id to `src/core/layers.ts` (the layer lists and the id type), write `src/layers/<id>.ts` exporting one `LayerArt` (copy the closest layer; the compiler lists every missing field), and add one import plus one entry to `src/layers/index.ts`. Nothing else switches on layers. A layer that reuses a sibling's piece imports it from that module (`critterCall: application.sound.critterCall`, `icon: drivers.stackTheme.icon`); pieces shared by several layers live in `src/layers/shared/` (`draw-kit.ts` pixel helpers, `ambient-kit.ts`, and the `*-props.ts` helpers several layers' entities draw with). Not per-layer data, so still in code: boundary crossing effects (tear at the syscall, mirror at VM exit, SMI freeze, ME 1-bit) in `scene.ts`, and the Endless/True Endless stack geometry in `core/layers.ts`.

## v4 world (entities and placement)

- Each layer has a library of 20+ entity types plus 1–2 anchor structures (in each layer's module, `src/layers/<layer-id>.ts`; `v4/libraries.ts` builds `V4_LIBRARIES` from every layer's `library` spec). An entity is `ent(id, sizes, draw, { anim, text, noFlip, cap, weight, floor, tags })`: `draw` is the static body, baked once per palette into a cached sprite; `anim` is a small live overlay on art time. Draw only through the `Pen` (`v4/kit.ts`), which snaps every solid colour to the band's palette; only `p.glow` (light) dithers.
- **One library builder (`v4/library.ts`, `buildLibraries`).** Every layer's `Library` is built from a `LayerSpec`: its own entities, its anchors, density, and an optional borrow `{ from, prefix, upTo }` that fills up to `upTo` types with renamed copies of the donor layer's own props (`${prefix}-${donor.id}`; the naming desk keys its records by these ids, so don't change the scheme). It `enforce()`s the 20-type minimum, unique ids, a donor big enough to fill, and that floor props and `floorOffset` go together. There is no other way to compose a library: Endless layers' extra props live in their own modules, and the Endless donor `mix()` is gone.
- **Entity metadata lives on the entity.** `floor: true` puts an entity on the layer's floor line (`floorOffset` in the spec; Libraries 4, Userspace 6); borrowed copies never keep it. `tags` overrides the entity's topic tags; unset, it gets its layer's defaults from its `topicTags` (`LAYER_TOPIC_TAGS` in `v4/libraries.ts` is read off the registry, so a new layer without tags is a compile error). Topic tags are never derived from id patterns (the old prefix regexes went stale), and `tagsForEntity(def)` throws on an entity that never went through the builder.
- Placement (`v4/place.ts`, pure and unit-tested in `place.test.ts`) runs once per (seed, viewport width), never per frame: anchors first, beside the centre; then a rejection-sampled scatter with bounded attempts that never overlaps, stays out of the cursor lane and keep-outs (arrival-title band, Ring −3 core and rails, floors), allows only small text-free props in the lanes under the console card and header chips, caps each type per screen height, picks least-used types first, and borrows neighbour types near band edges (bleed). A sparse fogged far plane sits behind. It `enforce()`s that libraries are complete, anchors fit and enough of the scatter lands.
- Seeding: two streams. Anchors (setpieces and landmarks) are seeded by the puzzle number, so everyone recognises the same world on a given day and it changes at rollover. Minor scatter and critters use a second stream derived from the same puzzle number, so the whole world is the same for everyone on a given day (decided 2026-11-26; per-visit scatter was tried and reverted). An Endless run instead seeds its world from its own run seed, so each run is a different world (and a resumed run the same one). `?seed=N` pins both. The debug rail's dice button rerolls it (its tooltip shows the seed for `?seed=N`). The rail's lane is kept clear in debug builds by dropping entities under it after placement, so the rest of the layout is identical to production.
- Known limit: panels are fixed to the screen and the world scrolls under them, so "keep-out under panels" is per x-lane, not absolute; the arrival title is kept clear for landings in a layer's first frame.
- System Biosphere (`src/render/critters.ts`): every layer has its own living critters animated on `artTime` (songbirds in Application, bouncy helper blobs in Runtime, bookworm blobs in Libraries, horned daemons in Userspace, brisk thread-bots in Kernel, fast bus-beetles in Drivers, sentinel drones in Firmware, twin mirror-wisps in Ring −1, frozen mid-leap silhouettes in Ring −2, 1-bit bit-motes in Ring −3). Each layer's `critters` spec has a set of `MotionType`s (`src/render/motion.ts`) and a `draw`; some layers add an alternate species on odd variants (`critters.alt`: its own motions and sprite, so a layer cannot have one without the other). Critters come with stereo-panned critter SFX (`sound.playCritter`) and visual chirp pips. Static scatter density (`library.density`) is tuned for breathing room, and literal static puns (`kr-watchdog` dog, `kr-oom` skull, static `us-daemon` / `kr-kthread`) were replaced with clean hardware props.

## Locked design decisions

- **Tiers.** Rarer means harder to reproduce. Frames per answer:

  | Tier | Frames |
  |---|---|
  | Off-by-one | 1 |
  | Works on my machine | 1 |
  | Null pointer exception | 2 |
  | Memory leak | 3 |
  | Race condition | 5 |
  | Heisenbug | 8 |
  | Bit Flip | 13 |

  - Works on my machine mirrors krillion's "Too Clever": the "obscure" pick everyone reaches for.
  - Bit Flip is exactly one hand-picked answer per question. Data loading enforces this.
- **Layers** (in `src/core/layers.ts`):
  - Thresholds: Application 0, Runtime 3, Libraries 6, OS userspace 10, Kernel 15 (syscall boundary), Drivers 22, Firmware 31, Ring −1 42, Ring −2 58, Ring −3 91. Rebalanced 2026-11-26 after a player-profile simulation showed the old ones kept typical players above the syscall and made the rings near-unreachable.
  - Intended feel: a typical day crosses into the kernel; a day of mostly deep cuts reaches Ring −1; Ring −2 needs at least one Bit Flip; Ring −3 needs a perfect day.
  - Only a perfect day (7 × 13 frames) reaches Ring −3. Tests pin these properties; change a test only on purpose.
- **Data model.** A term is stored once, with tags. Each tag carries that term's tier for that category, so "heisenbug" is Works-on-my-machine for "Name a type of bug". Each question queries one tag.
  - Duplicate keys within a category are a data bug and throw at load time.
- **Answer sets are swappable** (`AnswerSet` in `src/core/answers.ts`). Register new ones in `SETS` in `src/main.ts` to compare them in the debug menu.
- **Missed-answer reports and question submissions** go through prefilled GitHub Issue links. A GitHub account is required, and that's acceptable. Reports are never auto-accepted.
- **Day rollover:** local midnight, Wordle-style. `src/core/day.ts` has the epoch.

## Visual alternatives

Looks are drafted live:
1. Add an option to `LOOK_SLOTS` in `src/looks.ts`.
2. Branch on `look('slot')` where it's drawn, usually `src/render/scene.ts`.

The debug menu builds its controls from that table. Keep alternatives switchable rather than replacing the current look, so the user can compare them in the site.

Reduced motion must keep working: flashes, tearing, rain, flicker, cursor sway and bubbles all check `reducedMotion()`; the HUD adds `.still` so floating panels stop, and v4 art animates on a clock that is 0 under reduced motion.

Looks are saved under `nullion.looks.4`; bump the key when a default changes and old saved choices should not mask it.

The day's record of answers lives in the end-of-day card and the share text; there is no running panel. The card opens with its own centred summary card: `nullion #n` in the pixel face, the frame count and layer, then the stack as it stood on the right (the same `createLayerBadge` badges, top-down, deepest lit). When the day ends the right-hand blocks fly into those badges (`flyBadges` in `layer-stack.ts`, `EndCard.flyStackIn`, called by `Hud.endOfDay` after `flushTo`; reduced motion, or a stack that was not on screen, just shows them). Under it the card is a backtrace, most recent round first (#0 = the last answer): each row shows its tier's cursor icon, the **question** in the centre, and the frame numbers at the right beside the dropdown arrow. Hovering, focusing or tapping a row swaps the question for what the player did: the answer, the tier name and `+frames`. A small `↗` icon link at the collapsed row level opens what the question means in computing (`bankLink`, with an aria-label). The `▾` dropdown lists only the **other** answers to that prompt (see the answer-sheet bullet). Then, in order: a much larger full-width **Share result** button with `Next stack in …` right under it, **YOUR ALL-TIME STATS** (centred heading over two boxed blocks: the five totals, then every answer by tier), the Field Manual button, the issue links, a small **hide ▾** at the bottom and the build tag. Hide folds the whole card down into a slim **show ▴** bar (like the reveal's hide/show) so the world behind it can be looked at and clicked; show pops it back (`EndCard.stow`; reduced motion skips the fold and the pop; a new card always opens). There is no replay.

- **Field Manual (`writing/manual/` files, `src/game/manual.ts`; UI `src/ui/binder/`, the archive binder, in debug and production alike; design in `FIELD-MANUAL-PLAN.md`):** a searchable, collectible `MAN(7) · Field Manual` (Volume I: 38 approved entries across 10 living critters, 8 multi-layer families like *Small Ben* and *Lock Ness*, 17 iconic props, and 3 question-reactive anomalies, plus about 350 `draft` pages from the naming desk, shown in debug builds only). Every entry has a rarity tier. Each appearance is gated in the world by the seed and its shown % is measured (`src/game/rarity.ts`, see `FIELD-MANUAL-PLAN.md`). Hovering a clickable prop or critter in the live canvas shows rarity-colored corner brackets and a post-quantization status pill (`??? · Rare 9% · click` vs `logged` / `new layer!`); uncollected items occasionally pop a gentle `click me!` (or `?`) breadcrumb. Clicking logs the sighting without stealing input focus; clicks on the same prop within 0.7 s are ignored. Hover pills: a prop seen in this layer shows just its name in a quiet gray; an unseen one shows "???" (or the entry's name if it was found in another layer) with each letter and the outline flashing in the layer's own stack colours (no rarity, no "click"; the occasional breadcrumb is the same "???"). A first sighting takes a snapshot (white flash inside closing shutter brackets, then a white-framed photo of the prop lifts off toward the top-left); clicking a seen prop shows a red, wobbling "Already seen" with no name, and its gray pill hides meanwhile. Accessible via the title screen, a chunky glowing book button on the end-of-day card, and the debug rail (with an `Unlock all` toggle). The Portrait Index grid opens into a narrow, left-aligned reference page with the zoomed portrait on top, a separate `APPEARANCE` kicker + compact custom layer dropdown (detail note tucked into hover, untouched layers grayed out), name + rarity, and Prev/Next flipping. On phones (≤ 720 px) a spread is one scrolling page (the portrait leaf above its text, one running head and foot), the arrows and a horizontal swipe turn whole spreads, and a new page starts at its top.
- **Field Manual files (`writing/manual/<layer of first sighting>/<entry id>.md`, grammar and parser in `src/data/manual-format.ts`, loading and world checks in `src/game/manual-registry.ts`):** one Markdown file per entry, strict like `bank/` (errors name file and line). Source of truth; `MANUAL_ENTRIES` is what the registry loads.
  - Shape: a `# Name` line; `id: · tag: · kind: · rarity: · status: draft|approved` (optional trailing `· page: N`: its place in the chapter, lowest first, before entries without one, which follow by id); optional `<!-- comment -->` lines; the blurb (one line); a `> ` note line; `## Sightings` with `- <layer> · <entity id | critter | topic:<id>> · <detail note>` lines (detail note optional); optional `## Bugs`, `## Rumour` (one line each), `## See also` (`- <entry id>` lines), in that order. Sightings run shallowest layer first, one per layer; the file sits in its first sighting's layer folder.
  - Critters: `<layer> · critter` marks the layer's core species (it sets `critterLayer`, as before). Anomalies: `topic:<topic prop id>`. Everything else is an entity id in that layer's library.
  - `status`: production builds ship `approved` entries only; the draft files are left out of the bundle by the `virtual:manual-files` plugin in `vite.config.ts` (debug builds, the dev server and tests get all of them). Set `status: approved` after a human has reviewed the name, text and rarity.
  - **Load-time checks (`enforce()`):** every sighting must resolve to an entity in that layer's library, a layer critter species or a topic prop; ids unique; no entity, critter layer or topic claimed by two entries; every SEE ALSO names an entry. A stale file crashes loudly, so a renamed or deleted entity means editing its manual file.
  - **Style (`src/game/manual-style.ts`):** `manual-registry.test.ts` runs `styleProblems` over every loaded entry. ## Big screens

## Conventions

- Invariants use `enforce()` from `src/core/enforce.ts` and throw loudly. Expected conditions are handled explicitly, never with silent defaults. Missing localStorage is an expected condition.
- Keep game rules in `src/core` and `src/game`, free of DOM code, and test them.
- There is no hand-written answer set: the game, the debug build (its rail demos and `?endcard=1` play real answers from the live day's prompts) and the tests (`src/test-support/bank-set.ts`: seven approved categories loaded from `bank/`) all use the real answer bank. A test that names an answer names a real one.

## Stack modes (`src/core/modes.ts`)

`MODE_RULES: Record<StackMode, ModeRules>` (`rulesFor(mode)`) holds everything a mode decides: layer stack and max depth, prompt source (the day's 7 vs an anti-repeat pool), hearts (`hearts`, null for Daily) and the frames an answer pushes (`framesFor`), the watchdog, whether it persists the daily save / counts stats / shows the next-day countdown, whether a run is saved (`persistsRun`), round slots vs hearts, end-card headline, summary line, backtrace heading and chip, share title and glyph style (row or tally), world geometry (per-frame height, last-layer px), kernel-rain layer, unlisted crossing effect, sound-bed layer, realm nav, forced scroll mode, and scroll steps. `layersFor`, `maxDepthFor`, `layerIndexAt`, `layerAt`, `layerById` and `ANSWER_MS` also live there (`layers.ts` is layer data only). Never compare mode strings in callers: add a rule. Strings are compared only where they are identity (the `?endless=` param and debug dropdown in `main.ts` / `Hud.setEndlessMode`).

## Endless mode

**Released 2026-11-27:** players reach it through **Enter endless** on a finished day's end card (debug builds also have `?endless=1` and the header chip; True Endless stays debug-only). A 29-layer stack to about 2,500 frames (`ENDLESS_LAYERS` in `src/core/layers.ts`), a per-prompt watchdog that tightens with depth (`endlessAnswerMs`, in `src/core/modes.ts`), and an anti-repeat prompt bag drawn from the whole bank with a per-run seed.

- **Decided 2026-11-27 (owner):** Endless is offered only on a finished daily's end card, under Share result (never before the daily, like krillion; free). Entering lights the button up and drops into a run. **Hearts**, not strikes: 3; a timeout or skip costs one; a Bit Flip restores one; every 1,000 frames earned restores one (max 3); at 0 the run ends in a `KERNEL PANIC` card. No revives yet (pinned below). Prompts and answers may repeat within a run. Pacing target: a good player reaches the kernel in about 5 minutes and the rings in about 15, and about 10% of good runs reach the Landauer limit.
- **Frames (`ModeRules.framesFor`):** Endless pushes the tier's frames × `38 / (1 + depth / 400)`, easing off smoothly with depth (×38 at the top, ~×13 at the kernel, ~×5 near the bottom; never below the tier's own frames; `ENDLESS_FRAME_CURVE`); Daily keeps the locked 1–13. `scripts/endless-sim.py` (player profiles × curve × refill) chose the numbers: simulated good player at the kernel ~5.4 min, rings ~13.8 min, 10% at the Landauer limit, median run ~19 min. The profiles are guesses; retune from play data. Each round stores what it pushed (`Round.locked.pushed`); depth is their sum and hearts are replayed from the rounds (`Game.hearts`), so a restored run agrees.
- **Saved runs (`src/game/endless-save.ts`):** the run in progress lives under `nullion.endless.run` (snapshot with mode and seed; restore re-draws the seed's prompts and checks them), so reloads, closed tabs and new days resume it with wall-clock deadlines. A finished run is dropped and its depth kept as `nullion.endless.best` if deeper. Unusable saves are removed and reported. True Endless and debug settings never persist (`canPersistRun`).
- **The end card is generic (`EndCard`, `EndlessHook`):** a finished day offers **Enter endless** (or **Resume endless run**) under Share; a finished run shows its best ("New best" / "Your best"), **Re-enter endless** and **Back to today's stack**. Entering or re-entering teleports in (`Hud.teleportIn`): no title screen, a white flash, `nullion` with `ENDLESS` under it in the title face, then the run's first reading countdown. The backtrace heading is per mode (`ModeRules.backtraceHeading`), and the share's glyph line is a row for a day and a tally per tier for a run (`ModeRules.shareGlyphs`, `glyphLine` in `src/game/share.ts`).
- **The history bar (Endless top bar, `Hud.syncEndlessBar`):** the hearts, then the last 14 rounds (7 on a phone) as the same tier-cursor slots as the daily, with hover expansions; past 14, a dropdown on the left pages back by number ("1–14", "15–28"…); then the round counter.

## Answer bank

- **Source of truth: `bank/<domain>/<id>.md`**, one human-edited Markdown file per category. The strict grammar and its error messages live in `src/data/bank-format.ts`:
  - a `# prompt` line, then `id: · domain: · status:` (draft, approved or retired), then an optional `> Accepts:` line;
  - one `## <tier name>` section per tier, in tier order, holding `- answer | alias | alias` lines, each with an optional indented `note:`;
  - finally `## Inbox`, holding unreviewed candidates with `(suggested: tier)`. These are never accepted in play.
  - An approved category needs exactly one Bit Flip and at least one Works on my machine.
- **`bank/index.md`** is generated by `npm run bank:index` and is also the runtime manifest: `main.ts` picks the day's prompts from the approved rows, then lazily loads only those files (`src/data/bank.ts`, one chunk each; all approved files for Endless). `npm test` fails if the index is stale or any file is off-grammar.
- **Matching (`src/core/match.ts`, 2026-11-27):** a guess is checked in order: (1) exact name or alias, normalized (accents and punctuation dropped, but `+`, `#` and `*` are spelled out: C++, C#, A\*, MIP\* are their own names; the Python content scripts' `key()`/`norm()` must match, which `src/core/normalize-scripts.test.ts` checks); (2) other phrasings of the same answer, as exact: a leading a/an/the, a plural, then the prompt's own noun or a generic one on the end ("mutex locks", "ext4 filesystem"), smallest change first, and only when it names one entry; (2b) an answer's own name without the prompt's noun or a generic one ("Lorenz" for "Lorenz cipher"; `CategoryEntry.forms`), only after every phrasing of an exact name and only when one entry shortens to it; (3) four letters: an adjacent swap only, never a changed letter (ext3 ≠ ext4); (4) the typo budget (1 at 5+ letters, 2 at 9+). A one-typo correction on a 7+ letter name is `sure` and never asks, even with "ask first"; ambiguity is always rejected, never guessed. `bank.test.ts` checks across the approved bank that no phrasing lands on a different answer. `scripts/bank-dupes.py` lists entries that are one answer said two ways ("Sinusoidal" vs "Sinusoidal projection"), for merging.
- **Outside answers (debug prototype, 2026-11-27; `src/game/outside-check.ts`, debug menu "Outside answers"):** a guess the bank rejects is looked up on Wikipedia from the browser (exact title with redirects, then a search for "<guess> <head noun>"). It counts if the article is the guess (qualifier dropped), not a disambiguation or list, and its first sentence or a category contains the prompt's whole subject ("video codec"; a one-word compound may be split, "file system"). A title the bank knows scores that answer's tier (a missing alias); anything else scores the menu's tier (1, Race condition or Heisenbug) with a "found on Wikipedia, unverified" note (`Game.acceptOutside`). Days played with it on are never saved. Verdicts log to the console and `window.nullionOutside`. A live probe of 42 hand-picked guesses: 22/24 real answers accepted, 4/18 wrong ones (Deadlock, SQL, Defrag, Padlock: one-word subjects named in passing). Off in production: it sends guesses to Wikipedia.
- **What counts as an answer (decided 2026-11-26): named kinds.**
  - Anything experts name as a kind of the thing, in a real codebase, its docs or a paper, gets its own entry and its own tier. That covers designs (MCS lock) and named system primitives (Windows ERESOURCE, push lock and SRW lock; FreeBSD rmlock and sx lock; PostgreSQL LWLock and lock modes).
  - Plain bindings of a generic name are aliases of that name: `std::mutex` and `pthread_mutex` belong to mutex, `ReentrantLock` to recursive mutex.
  - API calls, specific instances (`mmap_lock`), config symbols and states never count.
  - A player gives one answer per prompt, so overlapping entries never double-score. The rule only decides what's accepted and whether a system's own name earns its own tier.
  - Category-specific limits go in the file's `> Accepts:` line.
- **Recall comes from real sources, not memory.** `scripts/mine-heads.py <bank file> <head,nouns> <dirs…>` mines phrases and identifiers ending in a head noun from source trees in `~/nullion-corpora/src`. Those are sparse clones: FreeBSD `share/man/man9`, MicrosoftDocs `windows-driver-docs` (kernel) and `win32` (Sync), and PostgreSQL docs plus `lmgr`. The output is noisy, so an agent applies the membership rule to it, and survivors go through the scorer into the Inbox. Add source trees per domain as categories need them.
- **Unconfirmed answers (decided 2026-11-26).**
  - A tiered line ending in `(auto)` was accepted by the pipeline and not yet confirmed by a person. It plays its **full tier**, and players are never shown that an answer is unconfirmed. An earlier Memory-leak cap made deep cuts pay 3 frames instead of 8 and was dropped.
  - `(auto)` is a review label only. Precision samples (95–100% on sourced answers) are the guard against wrong accepts.
  - Delete the marker to confirm an answer. Bit Flip and Works on my machine can never be `(auto)`.
  - The index counts unconfirmed answers per category.
- **Harvesting a category: one command** (error classes behind the steps: `research/inbox-review-2026-11-26.md`):
  `python3 -I scripts/bank/pipeline.py <id> [--from <stage>] [--dry-run]`, or `--batch N [--from-rank K] [--jobs J]` for the next N not-done categories in `design/triage/ranked.md` order (keep/fix only; `cut` is skipped, `merge` is noted). Stdlib only (`scripts/bank/llm.py` wraps the LLM calls).
  - Stages: plan (an LLM drafts `scripts/bank/plans/<id>.json` if missing; **flagged for the owner to veto**) → harvest → filter (two independent passes per batch with `prompts/filter.md`: A = Gemini via `agy`, B = Claude Haiku) → compare → escalate (Gemini; `"confidence": "low"` goes to the Inbox) → merge (merge-mined, score-candidates, `bank:index`; a fresh draft's Bit Flip and Works on my machine pins are chosen by Haiku and **flagged for the owner**) → obvious (Haiku drafts `scripts/bank/obvious-draft/<id>.json` if missing, then `apply-obvious.py`; **approval moves the list to `scripts/bank/obvious/`**, because `obvious.test.ts` rejects lists for non-approved categories) → dupes (report only) → links (`design/links/`) → precision (Haiku reviewer, **gate: 90%**) → report (`bank/reports/<id>.md` gets a pipeline section: gates, tier counts, pick shortlists, link coverage).
  - State: `scripts/bank/runs/<id>/state.json` plus `logs/<stage>.log`. Done stages are skipped on rerun; finished sub-steps (a valid filter pass) are reused; `--from <stage>` forgets that stage and later ones. The first failing stage or gate stops the run, non-zero, loudly (the filter fails when both passes keep nothing, and a fresh draft with under 10 surviving candidates stops before its pins are chosen). Sparse clones in a plan use non-cone patterns, so a path may be a single file. LLM output is schema-validated, retried once, then fails.
  - The category stays `status: draft`. Approval is a person's call: vet the flagged plan, pins and obvious list, fix what the precision sample found, then flip the status.
  - A plan may also use `extract` (regex over a registry file in a local tree, e.g. the Complexity Zoo's `classes.txt`) next to `heads` and `listings`.
- **Recall check (2026-11-27, `scripts/bank/recall.py <id>… | --approved [--no-llm]`):** a category's reference is a few Wikipedia categories (Haiku proposes them once, each must exist with 5+ articles, saved in its plan as `"reference": {"categories": [...], "by": "llm"}` for the owner to edit or veto). Their articles, minus a "(qualifier)" and a trailing generic noun, are matched to the bank with the game's normalization; the missing ones are judged with the missed-guesses triage (`misses.triage`, 25 per Haiku call), the real ones go to the Inbox, and recall = covered / (covered + real missing). Writes `design/recall/<id>.md`, `design/recall/summary.md` and `design/misses/recall-<id>.md`. Raw coverage without judging is meaningless (database: 8%: references hold concepts, tools and companies). `MIN_RECALL` (0.40) is a placeholder until calibrated on the approved bank; then it becomes a pipeline gate. Not run on all 45 yet (owner's allowance).
- **Missed guesses (2026-11-27):** every guess the bank rejects (typed, or submitted by the watchdog) is kept on the device (`src/game/misses.ts`, `nullion.misses`; counted per prompt, capped at 5,000). Settings → Missed guesses → Copy gives Markdown; paste it into `design/misses/<date>.md` and run `python3 -I scripts/bank/misses.py <file>` (`--no-llm` to only list): guesses the bank already knows are skipped, Haiku judges the rest per category, and real ones are appended to that category's `## Inbox` with a suggested tier; `<file>.triage.md` says what happened to each. The Inbox is never played, and an Inbox-only answer counts as a miss, never as known (triage and `recall.py` said "already in the bank" for them until 2026-11-27): promote with `python3 -I scripts/bank/promote-inbox.py <id>… | --approved` (suggested tier → `(auto)`; a name clash, Bit Flip or Works on my machine stays in the Inbox, with a reason).
- **Scope specs and the head-recall gate (2026-11-27):** `scripts/bank/scopes/<id>.md` (sub-kinds, In/Out rulings, examples per tier) is binding for every LLM stage; a new plan must map each sub-kind to a source (`covers`) and gets real Wikipedia categories to pick from (plans may use `wiki` sources). The pipeline's `recall` stage has Haiku list 60 answers players would type, judges the ones no tier accepts, puts real ones in the Inbox, and fails below `MIN_HEAD_RECALL` (0.85, a placeholder). First readings: unix-daemon 47% (its plan mined FreeBSD only), the new scheduling-algorithm draft 75%. Recall was capped by whatever 1-3 sources a plan picked (historical-cipher from one Python library, game-engine from ScummVM's engines).
- **Direction (decided 2026-11-27): source-first.** Like krillion deriving answers from IMDb tags, a category's answers should come from a stored, rerunnable query over structured data (Debian, Repology, Wikidata, kernel source, registries, macOS LaunchDaemons…), with familiarity from structured counts (Stack Exchange tags, popcon, sitelinks); LLMs only for aliases, noise and the recall probe. `scripts/fetch-corpora.py` fetches the datasets into `~/nullion-corpora`; `scripts/sources/` holds the per-category derivations; `research/structured-sources.md` lists the candidate sources and their licences (IMDb is non-commercial only).
- **Your edits win.** `scripts/score-candidates.py <candidates.json> ~/nullion-corpora` fills the tiers of a category that has none yet (a fresh draft). Once a file has tiered answers it never moves or deletes a line: it appends new candidates to the Inbox with a suggested tier, and `bank/reports/<id>.md` lists counts, scores and answers whose file tier differs from the scored tier by more than one.
- **Scoring:**
  - The corpora live in `~/nullion-corpora`, indexed by `scripts/index-corpora.py` with SQLite FTS5 and the porter tokenizer: dblp titles, arXiv cs title and abstract (`scripts/harvest-arxiv.py`) and kernel Documentation paragraphs.
  - Counts are normalised per category against the 3rd-largest count.
  - Absolute cut-offs (`CUTOFFS`, fitted to the pilot's judge calls) map score to tier, so adding obscure candidates never pushes common answers deeper.
  - Counts decide only with at least 10 hits in some corpus; below that the candidate's `judge` tier decides, and a weak candidate without one is an error. Bit Flip and Works on my machine are pinned.
- **Answer sets** are still swappable (`SETS` in `src/main.ts`, the debug menu's "Answer set"), but `bank` is the only one: the hand-written sample was deleted on 2026-11-27 so debug play matches the real game.
- **Status, 2026-11-27:** 45 approved categories (precision 95–100% on 20-answer samples; `Bit Flip` and `Works on my machine` picks carry 1-sentence `note:` whispers; the 11 approved 2026-11-27 have Claude-drafted ones awaiting the owner's skim, see REVIEW.md) and 148 drafts.

## Persistence

- **Daily save (`src/game/daily-save.ts`, `Game.snapshot/restore`):** today's game lives in localStorage under `nullion.daily.<puzzle>`: every round's accepted answer, extras, rejected guesses, timeout/skip flags, the phase and its deadlines. Reopening the same local day restores it exactly; a finished day reopens on the end card; the next puzzle number starts fresh and old saves are pruned.
- **Anti-cheese:** deadlines are wall-clock (`Date.now`, injected into `Game` as `now`; `src/game` never reads a clock). The reading start and the answer deadline are stored, answer deadlines chain from the end of reading, and a tick after being away replays reading, answering and the timeout. Closing, reloading or hiding the page never pauses or resets the watchdog.
- **Not saved:** Endless and every debug mode (unlimited, chosen date, no timer, scroll-only, `?depth`) never read or write the save (`canPersistDaily`). No storage is an expected condition: the game just doesn't persist. A corrupt or mismatched save is never silently reset: it is removed, a visible notice says why, and the day starts fresh.
- **Field Manual save (`src/game/manual-save.ts`, `ManualStore` in `src/game/manual.ts`):** version 2 under `nullion.manual.v2` (debug: `nullion.debug.manual.v2`). For each `(entry, layer)` appearance it keeps the first-sighting stamp `{ at, puzzle, prompt? }`, plus the set of "wet" stamps not yet viewed (unread). `main.ts` supplies the sighting context (puzzle, current prompt). Production migrates the old shared `nullion.manual.v1` key once (undated stamps); debug builds never touch it. A corrupt save is removed with a visible notice. Sightings of entries or layers that no longer exist are dropped with a notice naming them, and the cleaned save is written back. The debug rail's `Unlock all` toggle is an in-memory overlay that never changes saved discoveries.
- **End card:** counts down to local midnight, links into the Field Manual with any unread count, and offers a reload once the next puzzle opens.
